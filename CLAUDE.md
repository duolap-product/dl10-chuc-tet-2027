# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

"Chúc Tết 2027" (`online.duolap.tetviet`): a single-module (`:app`) Android app for Vietnamese Lunar New Year: countdown, greeting-card maker, Tết photos/music/customs, a wishing tree, and mini-games (Bầu Cua, Lucky Wheel, Ô Ăn Quan, Đập Chuột). Kotlin, XML layouts with ViewBinding (no Compose), Hilt, Room, Firebase, AdMob, and Play Billing. Code comments, log messages and default strings are in Vietnamese.

## Commands

```bash
./gradlew assembleDebug                 # debug build
./gradlew assembleRelease               # minified + shrunk, signed via keystore.properties
./gradlew testDebugUnitTest             # JVM unit tests
./gradlew testDebugUnitTest --tests "online.duolap.tetviet.game.oanquan.OAnQuanEngineTest"
./gradlew testDebugUnitTest --tests "*.MinimaxBotTest.someTestName"
./gradlew connectedDebugAndroidTest     # instrumented tests (device/emulator required)
./gradlew lint
```

- `app/build.gradle.kts` reads `keystore.properties` at configuration time to build the `release` signing config. If that file is missing, Gradle configuration fails for **every** task, including debug builds.
- Toolchain: AGP 9, Kotlin 2.2 with KSP (Room and Hilt compilers), Java 21. Dependency versions live in `gradle/libs.versions.toml`.
- Release builds also need real AdMob IDs as Gradle properties (`ADMOB_APP_ID`, `ADMOB_REWARDED_ID`, `ADMOB_INTERSTITIAL_ID`, `ADMOB_BANNER_ID`, `ADMOB_APP_OPEN_ID`). `preReleaseBuild` fails if they are missing or still Google test IDs. Each banner placement can have its own unit (`ADMOB_BANNER_TET_CUSTOMS_ID`, `ADMOB_BANNER_TET_PHOTOS_ID`, `ADMOB_BANNER_MUSIC_SELECTION_ID`, mapped in `AdManager.bannerAdUnitId`). These are optional and fall back to `ADMOB_BANNER_ID`. Rewarded and interstitial share one unit per format because they are preloaded before the placement is known. Debug builds always use test IDs (via `BuildConfig` and the `admobAppId` manifest placeholder).
- Bump `versionCode`/`versionName` in `app/build.gradle.kts` for releases (commits are titled "Release x.y.z-beta").

## Architecture

**Startup (`TetVietApplication`, `@HiltAndroidApp`)**: initializes Crashlytics/Analytics (collection is off in debug builds through the `firebaseCollectionEnabled` manifest placeholder and `!BuildConfig.DEBUG` in `AppCrashlytics`/`AppAnalytics`), the Room DB, `AdManager`, `BillingManager` and `TetMusicManager`, then launches a background Firestore sync for the card-maker collections. It also counts started activities so that background music pauses and resumes with app foreground state.

**DI (`di/`)**: everything is a `SingletonComponent` provider. `DatabaseModule` (DB, DAOs, `FirestoreSyncManager`), `MonetizationModule` (`VipPreferences`, `BillingManager`, `AdManager`) and `UpdateModule` (Play in-app update). Activities are `@AndroidEntryPoint`. Only `CardMakerActivity` and `VipActivity` use ViewModels; the other screens hold their logic in the Activity.

**Data layer**:
- Room `AppDatabase` (`tet_viet_local.db`) uses `fallbackToDestructiveMigration()` and `exportSchema = false`. Adding an entity or changing a schema means bumping `version`, and existing local data gets wiped. That is acceptable only because the content is re-synced or re-seeded.
- `FirestoreSyncManager` pulls the Firestore collections `tao_thiep_hinh_nen` (card backgrounds/stickers) and `tao_thiep_mau_sac` (card colors) into Room. Syncs are throttled to **once per day per collection** through `AppSyncPreferences` (to save Firestore quota). `forceRefresh` bypasses the throttle. `data_firestore/` holds seed JSON for these collections.
- Repositories (`data/repository/`) wrap the DAOs. `CardMakerRepository` falls back to `CardMakerDefaults` when no data has synced yet. `WishingTreeRepository` seeds initial wishes and exposes `Flow`s.
- Small per-feature state goes in SharedPreferences wrappers (`*Preferences.kt`: `VipPreferences`, `BauCuaPreferences`, game preferences).

**Monetization**: `VipPreferences` is the single source of truth (StateFlows `isVip` and `unlockedFeatures`). VIP status comes from `BillingManager` purchases/restore. Non-VIP users can unlock a feature temporarily by watching a rewarded ad (`AdManager` + `UnlockVipFeatureDialog` → `unlockFeatureTemporarily(featureId)`). Gate features with `isFeatureUnlocked(featureId)`. `AdManager` skips ads for VIP users. All purchase UI (the Home VIP button, the Settings VIP card, the "Nâng cấp VIP" button in `UnlockVipFeatureDialog`, VIP card fonts) is hidden while `BuildConfig.IAP_ENABLED` (set in `app/build.gradle.kts`) is `false`, which it stays until the Play Console products are configured. Check the flag in any new purchase entry point. Settings also has "Mời cà phê" (`DonateCoffeeDialog`): three consumable in-app products in `BillingManager.DONATION_PRODUCTS` (`tetviet_donate_coffee`, `tetviet_donate_milk_coffee`, `tetviet_donate_coffee_cake`). `BillingManager` grants VIP only for the products in `VIP_PRODUCTS`; donation purchases are consumed and reported through `donationCompleted`, which `MainActivity` turns into a thank-you dialog. Unlike VIP, the donate row is always shown (not gated by `IAP_ENABLED`). Donations must stay on Play Billing: a personal bank QR or external payment link inside the Play build risks the Payments policy.

**Ads (`ads/`)**: AdMob is initialized from `MainActivity` only after UMP consent (`AdConsentManager`), not in `Application`. Every `show*Ad`/`attachBanner` call takes an `AdPlacement` (used for Analytics events `ad_shown`/`ad_skipped`/`ad_reward_earned`/`ad_load_failed`). Interstitials are gated by `AdPolicy` (none in the first 3 minutes after install, 60s interval, 60s after a rewarded ad, caps of 6 per session and 15 per day). Call sites should check at every natural break and let `AdPolicy`'s time rules set the frequency, rather than adding their own every-N-actions counters; `TetVietApplication` feeds it foreground/background events. `showInterstitialAd`'s `onDismissed` always fires, even when the ad is skipped, so put the user's next action there. Show interstitials only at natural breaks (after a dialog closes), never over a result sheet. App Open (`onAppForeground`, called from `TetVietApplication` when the first activity resumes after the app comes to the foreground; calling `show()` in `onStart` fails because the SDK still sees the app as backgrounded, and on Samsung even `onResume` can be too early, so `AdManager` waits up to ~1s for the process to reach foreground importance) only shows on a warm return after at least 30s in the background, at most once per 6h, never in the first session, and shares the 60s full-screen spacing with interstitials. Call `AppOpenGate.skipNextForeground()` before sending the user out on purpose (share, Play billing/update, external links). Widget and notification intents carry `AppOpenGate.EXTRA_SKIP_APP_OPEN`. Banners (`attachBanner` into a `bannerAdContainer` FrameLayout at the bottom of the layout) are only on content screens (Customs, Photos, Music), never on games, the card editor or the wheel. Đập Chuột uses two rewarded placements (`DAP_CHUOT_REVIVE`: +10 s once per game when time runs out, `DAP_CHUOT_DOUBLE_COINS`: on the result card) and one interstitial (`DAP_CHUOT_BREAK`), shown only after the result card closes (Play again or Exit). Ô Ăn Quan follows the same pattern: `OAN_QUAN_HINT` (the first hint each game is free, later ones are rewarded), `OAN_QUAN_UNDO` (vs-bot mode only; reverts the player's last move and the bot's reply, also offered once per game on the loss card), `OAN_QUAN_DOUBLE_COINS` on the win card, and the `OAN_QUAN_BREAK` interstitial after the result card closes or when the player abandons a game in progress with "Ván mới". On the Wishing Tree, the `WISHING_LANTERN_BREAK` interstitial is checked when the lantern greeting dialog is dismissed. The daily check-in offers `DAILY_CHECKIN_DOUBLE` (rewarded x2).

**Home game zone and daily check-in (`home/`, `checkin/`)**: the top of `MainActivity`'s scroll content is `layout_home_game_zone` ("Sân Chơi Ngày Tết"), driven by `HomeGameZoneController`. It shows the coin balance, the 7-day check-in card and the Bầu Cua / Ô Ăn Quan / Đập Chuột cards (the old `cardOption2/4/5` in the explore row are kept but `gone`). Coins are the shared `BauCuaPreferences` wallet. `DailyCheckInPreferences` holds the streak (rewards `REWARDS` 10→50, day 7 = 100; missing a day restarts at day 1; days are Vietnam days via `TetCountdown.dayIndex`); its pure `statusFor` is unit-tested. It replaced Bầu Cua's old daily gift, so Bầu Cua opens the same `DailyCheckInDialog`. Bầu Cua's "watch video for coins" pays `videoRewardFor` (x2 today's reward, capped at `VIDEO_REWARD_CAP` = 100 per video). The number of videos is deliberately unlimited. Coin gains animate with `views/CoinFlyAnimator` (coins fly on a curve into the balance, which counts up); for rewarded ads, credit coins in `onUserEarnedReward` but run the effect in `onDismissed`, and `hold` the balance view so a Flow update does not jump ahead of the animation. `DailyCheckInReminder` posts a 19:00 reminder when today isn't claimed (inexact alarm, stops after 3 idle days, toggle in Settings).

**Home-screen widgets (`widget/`)**: there are two widgets, both extending `TetWidgetProviderBase`, which handles the midnight RTC refresh alarm (one per provider class), time/locale broadcasts and `requestPin`. Use only RemoteViews-safe views in their layouts.
- `TetClassicWidgetProvider` (`widget_tet_classic`): pill frame with gold clouds, showing calendar days until Tết (`calendarDaysUntilTet`).
- `TetLixiWidgetProvider` (`widget_tet_lixi` / `_large`): full days plus a `Chronometer` counting down to Vietnam midnight, a progress bar, the lunar date (`LunarCalendar`) and, in the tall layout, a daily wish. On Android 12+ both layouts go in one size-mapped `RemoteViews` because Samsung's reported sizes are unreliable.

Settings → "Thêm widget" opens `dialog_widget_picker`, which previews each widget by applying its real `createViews()` RemoteViews. `TetCountdown` is the single source of the Tết dates (`MainActivity` uses it too), so change them only there. Renaming a provider class removes users' existing widget instances.

**Games (`game/<name>/{engine,ai,ui,online}`)**: game rules are pure Kotlin `object` engines (`OAnQuanEngine`, `WhackMoleEngine`) that operate on mutable state classes and return step lists for the UI to animate. They have no Android dependencies, which is what the unit tests in `app/src/test/.../game/` cover, so new game logic belongs in the engine. Đập Chuột's UI (`game/dapchuot/ui`) is `MoleHoleView` (one hole: back, clipped mole, front lip, plus its pop/hit/idle animations) and `DapChuotEffectsView` (Canvas particles); its art is the `ic_dc_*`/`bg_dc_*` vectors (the old `activity_dap_chuot.xml` and `ic_mole_*` are kept but unused). Ô Ăn Quan also has a minimax bot (`ai/`; `MinimaxBot` evaluates for the side passed to its constructor, so hints build one for `currentTurn`), a custom-drawn board `OaqBoardView` (it keeps its own copy of the state and replays the engine's step list from the pre-move snapshot that `animateSteps` receives; call `setBoardState` with the real state afterwards. The old `OAnQuanBoardView` and `activity_o_an_quan.xml` are kept but unused), and online multiplayer through Firestore rooms (`OAnQuanOnlineManager`, which maps `OAnQuanRoomData` ↔ `OAnQuanBoardState`).

**UI conventions**: custom views live in `views/`. Adapters are split between `adapter/` and the newer `adapters/` package. Strings come in Vietnamese (`values/`, the default) and English (`values-en/`), so add every new string to both. Fonts must cover Vietnamese diacritics. Use `arimo_bold`/`arimo_regular` (metric-compatible replacements for Liberation Sans), `lobster_regular` and `pacifico_regular`. The old `liberationsans_*`/`lobstertwo_*` files are kept in `res/font` but miss 48–54 Vietnamese glyphs, so don't use them. Check a new font's cmap before adding it. OFL licenses are in `assets/licenses/`. VIP-only card fonts live in `VipCardFontManager` (`CardMakerModels.kt`); locked ones open `UnlockVipFeatureDialog.newVipOnlyInstance`, which has no rewarded-ad unlock. Analytics and Crashlytics go through the `AppAnalytics` / `AppCrashlytics` wrappers.

**R8**: release builds are minified. `app/proguard-rules.pro` keeps `data.model`, `data.local`, `data.sync`, `views`, and the `game.oanquan`/`game.dapchuot` packages, because Room and Firestore depend on reflection. A new package with Firestore-mapped or reflectively used classes needs a keep rule.
